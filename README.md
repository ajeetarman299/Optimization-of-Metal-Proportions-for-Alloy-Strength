# Optimization of Metal Proportions for Alloy Strength

A machine learning framework that predicts the fatigue strength of an alloy from its metal proportions, then searches the composition space for proportions that maximize predicted strength.

## Results

CatBoost was the strongest model. The original project summary reports **91.7% training and 88.5% validation accuracy** for it.

Hold-out results saved in the notebook (70/30 train and test split, `random_state=0`):

| Model | Test MSE | Test R2 |
| --- | --- | --- |
| Bagging (decision trees, `max_depth=5`, 100 estimators) | 354.49 | 0.816 |
| Extra Trees (default settings) | 331.38 | 0.828 |
| Random Forest (GridSearchCV: `max_depth=15`, `n_estimators=1000`) | 245.45 | 0.873 |
| **CatBoost (default settings)** | **219.41** | **0.886** |

- Bayesian optimization of the CatBoost hyperparameters (55 trials, each scored on the same hold-out split) reached a best MSE of 210.8.
- Using the trained CatBoost model as a surrogate, a random search over 1,000 candidate compositions found a best predicted fatigue strength of 160.45.

## Approach

1. **Data preparation.** Each row is an alloy with the proportion of 21 elements (Al, Fe, Si, Zn, Cu, V, Zr, Ag, Mn, Ni, Sn, Be, Ti, Mg, B, Ga, Cr, Pb, Bi, Li, Co) and its fatigue strength. The temper (O, F, H or T series) is parsed from each alloy's source URL and label encoded, and missing element values are filled with 0.
2. **Features and target.** The metal proportions and the encoded temper are the features; fatigue strength is the target.
3. **Model comparison.** Bagging, Extra Trees, Random Forest and CatBoost regressors are compared on hold-out MSE and R2, and a LightGBM grid search is also set up. Hyperparameters are tuned with GridSearchCV, RandomizedSearchCV and Bayesian optimization.
4. **Composition search.** The trained CatBoost model predicts strength for candidate compositions generated by:
   - a grid over the five most important features (10 values each), and
   - random sampling of each feature within the range observed in the data.

   The composition with the highest predicted fatigue strength is reported as the optimum. Random Forest surrogates are used for the same search as a comparison.

**Note:** candidates are sampled one feature at a time, so the proportions are not constrained to sum to 100 percent and the encoded temper is treated as a continuous value. Treat the optimum as a model-guided starting point for alloy design, not a validated composition.

## How to run

1. Clone the repository:

   ```bash
   git clone https://github.com/ajeetarman299/Optimization-of-Metal-Proportions-for-Alloy-Strength.git
   cd Optimization-of-Metal-Proportions-for-Alloy-Strength
   ```

2. Create an environment and install the dependencies.

   With [uv](https://docs.astral.sh/uv/):

   ```bash
   uv venv --python 3.12
   source .venv/bin/activate
   uv pip install -r requirements.txt
   ```

   Or with pip:

   ```bash
   python3.12 -m venv .venv
   source .venv/bin/activate
   pip install -r requirements.txt
   ```

3. Provide the data: an Excel workbook with a sheet named `fatigue_strength` that holds one column per element, a `Fatigue Strength` column and a `url` column with the MakeItFrom.com page of each alloy (the temper code, such as `-H112-`, is parsed from the URL). Update the path in the `pd.read_excel(...)` cell to point to your file.

4. Start Jupyter and open the notebook:

   ```bash
   jupyter lab
   ```

Notes for running locally:

- Skip the first cell (it mounts Google Drive and is only needed on Colab) and the `pip install` cells (`requirements.txt` covers the dependencies).
- The notebook is an exploratory log, not a pipeline, so run it cell by cell rather than all at once. Some search cells raised errors in the saved run (the full-grid, TPOT and `evolutionary_search` cells) and some are very long-running (for example the 1,000,000-sample random search). TPOT and `evolutionary_search` are not part of `requirements.txt`, and the rest of the workflow does not depend on them.
